As of 2026-08-08 the TAPP library is **composed, not copied**. Shared field blocks live in `Claude Skills for TAPP/modules/` as a CSV + JSON manifest and are built into consuming TAPPs by `scripts/compose_tapp.py`. This is **Rule 6** in `references/conventions.md`.

**14 live modules** as of 2026-08-27 (+3 retired) (+2 retired rows carried in the register). Run
`Project Files/Scripts/build_module_register.py` for the current table rather than trusting a list
here — it prints fields, blocks, version and consumer count per module. Current shape:
Core (**31** fields, 16 consumers) · **ICPMS (39, 9)** · **CompositionQC (6, 12)** · **CollisionCell (6, 6)** · LaserAblation (**29**, 6) · SolutionIntroduction
(16, 3) · MCICPMS (15, 3) · UPb (15, 3) · Geochronology (6, 3) · Aggregation (2, 13) · SamplingUnitSelection (2, 13) ·
Analyte (1, 13) · Blank (1, 12) · CalibrationFactor (1, 14). Retired and carried: Group1, ReportingCore, **ArAr**.

**Retiring a module is a MOVE, not a delete:** files go to `Archive/Superseded Modules/`, and
`build_module_register.py` carries forward any register row whose files are gone. Write the reason
into the manifest BEFORE moving, so the archived copy explains itself.

**`Module_CompositionQC` (v1, 2026-08-27)** owns the 5 QC fields shared by the 12 TAPPs that report
calibrated composition — absent from exactly the 4 imaging/structural ones (SEM_Imaging, SEM_FIBSEM,
TEM, Lab-XCT). It took those 5 fields from **5 distinct descriptions each to 1**. Note the contrast:
the Description/Purpose split was measured NOT to make descriptions converge; **extraction is what
converges them**. `Primary Calibration Standard Name` and `Sample Preparation Method` were left out —
see precedents.md.

**Sort module candidates by whether their columns ALREADY AGREE, not by size.** The 10-field
LaserAblation extension and the 6-field CollisionCell looked equivalent; one was a zero-content
transfer written the same hour, the other needed six merges by reading. The query is cheap — run it
before choosing. Also: `compose_tapp --out` mutates `composed_tapps.json` as a side effect, so a
script that composes then validates must be able to roll the register back.

**`Module_ICPMS` is complete at 39 fields (v5, 2026-08-27)** — all the ICP-MS-specific fields
identified at extraction. The last one in, `Analysis Sequence`, was blocked for a day by a tier
divergence and moved in once that was resolved; see [[project-tapp-description-purpose-split]] and
the module's own `decisions` log, which is the best-documented thing in the library.

**All eight gained Column I (`Keyed By`) on 2026-08-11** under Rule 7, module-owned alongside A–E; `owned_columns` in every manifest gained `"I"`. Module versions were bumped for that change and again for the Rule 7.4 invariant pass — check the manifests rather than assuming.

**Why:** geochronology is a *reported-quantity class*, not a technique — so it became modules composed onto instrument TAPPs rather than a TAPP of its own. Two geochronology TAPPs were retired as a result.

**How to apply:**
- **Never hand-edit a composed group in a TAPP** (Group 1 always; others per `composed_tapps.json`). Edit the module, recompose, verify with `--check`.
- Before creating a module, read Rule 6 — especially **6.10**: modules are *extracted, not invented*, need a second real consumer, and need 5+ coherent fields. Below that, Rule 4 propagation is cheaper.
- A field must both **recur across TAPPs** and **not already exist in the library under another name**. The second condition is the one that gets missed.
- `composed_tapps.json` records which modules built each TAPP. It is **no longer hand-maintained**: `compose_tapp.py` writes it via `record_composition()` (carrying an entry forward across a version bump), and the module register is generated by `build_module_register.py`. Verify with `recompose_all_20260812.py --check` (expect all 16 MATCH) and `build_module_register.py` (expect "register is up to date").
- **`validate_tapp.py` is NOT sufficient before a bump — run `compose_tapp.py --check` too.**
  Learned the hard way 2026-08-30: six MODULE-OWNED Column E cells were retyped directly in the
  TAPP CSVs across two commits. `validate_tapp.py` stayed 0 WARN throughout because it does not
  compare modules against TAPPs; only `compose_tapp --check` does, and recomposing any consumer
  would have silently reverted the work. **Check module ownership BEFORE editing any field**
  (`grep -l "<field>" "Claude Skills for TAPP/modules"/*.json`), and gate on
  `--source <tapp> --module <MOD> --check` returning MATCH for every consumer pair.
- **Use `Project Files/Scripts/check_field_ownership.py`, never an inline glob.** The one-liner
  I used caused Rule 6 violations TWICE (2026-08-30 and again in the B8 commit): run from a
  subdirectory its relative glob matched nothing, the loop body never ran, and control fell to
  `else`, printing a confident "TAPP-owned". **"No module owns this" and "I looked in the wrong
  place" were indistinguishable.** `Primary Calibration Standard Name` (Module_CompositionQC)
  was edited in 12 TAPPs on that answer. The script resolves the module dir from its own path
  and errors if it finds no manifests.
- **`compose_tapp.py` records against the `--out` path.** Composing to a temp file and moving it
  writes the wrong path into `composed_tapps.json` and leaves `module-version-drift` WARNs. Pass
  `--out` equal to the real file (in-place is safe) or the record is lost.
- Module JSON `version` is a **string**; bump it as `str(int(v)+1)`.
- Run `scripts/validate_tapp.py` before any version bump. Baseline as of **2026-08-30: 0 ERROR / 0 WARN / 40 INFO** across 16 TAPPs (jumped 23 -> 41 when `colf-divergence` shipped 18 triaged entries, then 41 -> 40 as `Plasma Thermal Mode` was harmonised off the backlog). Earlier baselines for comparison: 23 INFO (2026-08-30, pre-7.8.11), 37 INFO (2026-08-27), 56 INFO (2026-08-26), 9 findings (2026-08-11), 395 (2026-08-10, 14 TAPPs). The INFO set is all registered/triaged divergence — a rising count is not automatically bad, but an unregistered one is.

- **A module extension can be a zero-content change.** When every module-owned column already matches across the consumers, composition rewrites them to what they already hold and the only cell that moves is the Column G provenance stamp `Source: <module> module`. Confirm with `--check` before writing: it reports the exact cell count per TAPP.

**Hard-won lessons, both recorded because they recur:** a **name-only diff over-reports field gaps in both directions** — only reading descriptions closes it (cost: one wrong retirement claim, one wrong Rule 1 claim). And **description length is not a quality proxy**; the `description-source-leak` check exists because longer descriptions were often longer only from literature-provenance leakage.

Related: [[reference_la_icpms_lineage]], [[reference_skill_paths]], [[project_tapp_keyed_by_rule7]].

**A dry run must never open a file for writing.** `with open(path,"w") as fh: write() if apply else
None` truncates the moment the `with` runs — the conditional only decides whether to *write back*.
A dry run of `universalise_spm.py` emptied all 16 TAPP CSVs this way. Recovered in full from
`Current TAPPs/`, which is the mirror's real purpose: it is the only tracked copy of the live files,
so **sync and commit before any bulk write**.
