The user made "Constants and Reference Values Used" a mandatory field across every TAPP in the project — a new Rule 5 in `references/conventions.md`, mirroring how Rule 3 mandates "Analytical Mode". The field documents physical constants and reference values used in data reduction (decay constants, standard isotope ratios, etc.), distinct from Group 6's Reference Material Information (which covers accepted values of specific calibration materials, not universal physical constants).

**Why:** decay constants and standard isotope ratios get revised over time — concrete precedent: ²³⁸U/²³⁵U was long assumed constant at 137.88 (Steiger & Jäger 1977) until Hiess et al. (2012) showed it varies in nature, and many labs now use 137.818 or sample-specific values. A reported age or ratio can only be correctly reinterpreted against a future revision if the constant originally used is documented. The field originated while building the standalone [[project_horstwood_geochron_tapp|Horstwood-derived LA-ICP-MS Geochronology test TAPP]], triggered by Horstwood et al. (2016)'s own Table 4 footnote ("Decay constants of Jaffey et al. (1971) used") — information their Table 3 metadata template never captured as a structured item.

**Execution:** A prior session wrote a full retrofit briefing (`Project Files/Design Notes/RETROFIT-BRIEFING_Constants-Field-Rule5.md`, was in the project root) rather than executing directly, flagging one open question for the user to resolve first: should the field be added to literally every TAPP (including pure-imaging/morphology techniques, recording "None"), or scoped only to techniques with plausible constant-dependent data reduction? A later session read the briefing in full, then confirmed via AskUserQuestion before touching anything.

**Scope decision (user-confirmed 2026-07-28): fully universal.** Every TAPP gets the field, including SEM_Imaging and Lab-XCT (pure-imaging/morphology techniques), which record "None". This was the briefing's own recommended default, matching Rule 3's precedent that even single-mode/not-applicable cases still get the field — field presence itself is informative, distinguishing "deliberately none" from "nobody asked."

**Canonical field:** `Constants and Reference Values Used`, last field in Group 5 (Data Processing), C=Basic, D=Editable, Text (free), Y across all mode-flag columns. Full text in Rule 5, `references/conventions.md`, and the matching precedent entry under "Group 5: Data Processing" in `references/precedents.md`.

**Retrofitted — 11 TAPPs, all integer version bumps, xlsx regenerated for each:** EPMA v8→v9, LA-Q/SF-ICP-MS v4.1→v5, SEM v5→v6, SEM_Composition v5→v6, SEM_Imaging v5→v6, SEM_FIBSEM v5→v6, Solution MC-ICP-MS v3→v4, Solution Q-ICP-MS v6→v7, Solution SF-ICP-MS v6→v7, TEM v8→v9, Lab-XCT v9→v10. Prior versions left unchanged on disk (filename-based version control). Did **not** touch the stale, frozen `LA-ICPMS_TAPP_v13.csv` branch — see [[reference_la_icpms_lineage]] — nor re-touch the standalone Horstwood test TAPP, which already carries the field from its own v5 under a geochronology-specific description (a comparison exercise, not part of this production set). Full record: dated entry `2026-07-28 | CROSS-TAPP | Rule 5 — "Constants and Reference Values Used" added to all TAPPs` at the end of `TAPP_Development_Log.md`, plus Part V item 5 updated to show resolution.

**One deliberate deviation from the briefing's draft patch script:** the briefing suggested setting the Comments column (G) to a "Source: In-house TAPP rule — Rule 5..." provenance note. Verification before patching (checking the actual "Analytical Mode"/Rule 3 field's Comments column across EPMA/TEM/Lab-XCT) showed the real cross-TAPP convention for a Rule-mandated universal field is an **empty** Comments column — `conventions.md` documents column G as short WDS/EDS/Analyte-Specific labels only, not rule-provenance notes. Followed the verified real convention instead of the briefing's draft.

**Two pre-existing issues surfaced during the retrofit's structural audit, deliberately not fixed (out of scope for this pass, noted in the dev log entry):**
1. Five TAPPs have no blank separator row between Group 5 and Group 6 — SEM_Composition, SEM_Imaging, SEM_FIBSEM, Solution Q-ICP-MS, Solution SF-ICP-MS — contrary to the documented "one blank row between groups" convention. Worked around by inserting the new field as the new last Group 5 row in each; the missing separator itself was left as found.
2. `Analytical Mode` (Rule 3) is absent from all three Solution ICP-MS TAPPs (MC-ICP-MS, Q-ICP-MS, SF-ICP-MS) — a real Rule 3 compliance gap. Consistent with the 2026-06 Analytical Mode retrofit list in `precedents.md`, which never covered this family — pre-existing, not introduced by this work.

**Dev-log coverage note:** individual per-technique `### vN` Version History entries were not added for this change — followed the 2026-07-24 VIM3 migration's own precedent ([[project_tapp_vim3_terminology]]) of one consolidated CROSS-TAPP dated entry for a uniform whole-library change, rather than duplicating the same note across every Part. EPMA, SEM (and its three sub-TAPPs), TEM, and Solution MC-ICP-MS have no dedicated Part in `TAPP_Development_Log.md` at all — the consolidated entry is their only record of this version bump.
